Linked Lists

Breaking free from the constraints of contiguous memory.

A Linked List is a physical, linear data structure where data is stored in scattered, non-contiguous memory locations. Instead of living side-by-side like in an array, elements are stored in independent Nodes. Each node holds its data and a pointer that acts as a map to the next node in the chain.

Advantages

Dynamic Size: The list can grow and shrink infinitely at runtime. Efficient Insertions/Deletions: Adding or removing a node anywhere only requires changing a couple of pointers, without shifting massive amounts of data (O(1) if location is known).

Disadvantages

No Direct Access: You cannot instantly jump to index 5. You must start at the beginning (Head) and follow the pointers one by one (O(N) search time). Also requires extra memory for storing the pointers.

Singly Linked List

In a Singly Linked List, traffic only flows one way. Each node knows about its data and the next node. The list is accessed via a head pointer.

Core Operations:

1. Insert First (Add to front)

Create a new node, point its next to the current head, and update the head pointer to this new node.

Node* temp = new Node(val); temp->next = head; head = temp;

2. Delete First (Remove from front)

Save the current head in a temporary pointer, move the head to the second node, and delete the temporary pointer to free memory.

Node* temp = head; head = head->next; delete temp;

3. Search

You must traverse the list node by node until you find the element or hit NULL.

Node* current = head; while(current != NULL) { if(current->elem == target) return current; current = current->next; }

Doubly Linked List

In a Doubly Linked List, traffic flows both ways. Each node contains a pointer to the next node AND a pointer to the prev (previous) node.

class Node {
public:
    int elem;
    Node* next;
    Node* prev;   // The backward pointer
};

Why use a Doubly Linked List?

While it requires more memory per node (for the extra pointer), it allows you to traverse backwards. It makes deleting a node much easier if you only have a pointer to that specific node, because you can immediately access its predecessor via node->prev.
